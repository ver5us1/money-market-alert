# План развития

## Реализовано в коде

- Telegram-меню и сохранение подписок.
- Сбор Finnhub и проверка повторных ID.
- Текстовый фильтр, анализ Ollama и проверка JSON.
- Хранение анализа и выбор уведомлений по важности.
- Форматирование сообщения и учёт доставки.
- Последовательный pipeline и настройки партий.
- Автономные тесты, сценарий PostgreSQL и конфигурация CI.

## Следующий этап

- [ ] Проверить полную цепочку с реальными сервисами и тестовым получателем.
- [ ] Зафиксировать проверенные версии зависимостей.
- [ ] Подготовить размеченный набор новостей для оценки релевантности и важности.
- [ ] Измерить время анализа, задержку уведомления и рост очереди.
- [ ] Добавить лимит повторов анализа и управление постоянными ошибками.
- [ ] Определить правила восстановления зависших `pending` без лишних повторов.

## Дальнейшие изменения

- [ ] Связать одну новость с несколькими компаниями.
- [ ] Разделить сбор и анализ при росте объёма данных.
- [ ] Добавить миграции схемы PostgreSQL.
- [ ] Расширить параметры подписок и наблюдаемость обработки.

Текущий MVP не обучает собственную модель и не имеет опубликованных метрик качества. Простое совпадение названия может ошибаться, а строгий текстовый фильтр — пропускать косвенные упоминания. Эти ограничения проверяются на размеченных примерах, а не снимаются оформлением репозитория.
