# Работа над проектом

MONEY Market Alert находится в разработке. Изменения должны сохранять понятную структуру и актуальную документацию.

## Ветки

| Ветка | Назначение |
| --- | --- |
| `main` | Оформленное состояние проекта для просмотра и публикации |
| `develop` | Основа дальнейшей разработки и объединения изменений |
| `feature/<task>` | Новая возможность, например `feature/news-retry-limit` |
| `fix/<task>` | Исправление ошибки, например `fix/duplicate-alert` |
| `docs/<task>` | Изменение документации, например `docs/update-use-cases` |

Постоянные ветки — `main` и `develop`. В начальном пакете они указывают на один коммит. Ветки задач создаются от `develop` под реальную работу; после объединения их можно удалить. Дополнительных веток с пустыми или вымышленными изменениями в пакете нет.

Изменения задачи объединяются через pull request в `develop`. Подготовленное состояние затем переносится из `develop` в `main`. Наличие `main` не означает, что MVP завершён: статус отражается в README. Защита веток на GitHub настраивается отдельно после публикации.

## Коммиты и pull requests

Один коммит — одно понятное изменение. Префиксы: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`. Например: `docs: clarify MVP scope`.

В pull request опишите проблему, итоговое изменение и выполненную проверку. Изменения API, схемы БД и пользовательских сценариев сопровождаются обновлением соответствующих документов. Не включайте ключи, реальные выгрузки БД, окружения и кэш.

## Размещение кода

| Компонент | Каталог |
| --- | --- |
| Интерфейс Telegram и доставка | `src/money_market_alert/bot/` |
| Finnhub и Ollama | `src/money_market_alert/services/` |
| Проверка результата анализа | `src/money_market_alert/analysis/` |
| Запросы PostgreSQL | `src/money_market_alert/storage/` |
| Схема и описание БД | `database/` |
| Требования и модели | `docs/requirements/`, `docs/models/` |

Импорты используют имя пакета `money_market_alert`. Исходные документы не заменяют описание текущего кода: при расхождении обновляйте Markdown-документацию и сохраняйте контекст оригиналов.

## Проверки

Автономные тесты выполняются через `unittest`; обращения к HTTP и Telegram в них заменены имитациями. Сценарий PostgreSQL разрешён только для отдельной тестовой БД с суффиксом `_ci` и включается явным флагом.

GitHub Actions устанавливает пакет, проверяет импорты и синтаксис, создаёт тестовую PostgreSQL БД, выполняет проверки и демо. Успешный CI не заменяет проверку реальных Finnhub, Ollama и Telegram.

Формат текстовых файлов: UTF-8, окончания строк LF, четыре пробела в Python. Правила заданы в `.editorconfig` и `.gitattributes`.
